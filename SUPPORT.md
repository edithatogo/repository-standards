# Support

## Getting help

Start with the affected repository's README, documentation, examples, release
notes and existing issues. Check its supported versions and maintenance status.
Repository-specific support instructions take precedence over these shared
defaults.

## Where to ask

| Need | Route |
| --- | --- |
| Usage or setup question | Use the repository's documented help channel. If Discussions is enabled and a suitable category exists, use it; otherwise open a concise issue in that repository. |
| Reproducible defect | Use its bug-report form and provide a minimal safe reproduction. |
| New capability | Use its feature-request form and describe the problem, alternatives and observable acceptance criteria. |
| Missing or incorrect documentation | Use its documentation form and identify the affected page, section and version. |
| Suspected security vulnerability | Follow the [security policy](https://github.com/edithatogo/.github/blob/main/SECURITY.md); keep vulnerability details out of public issues. |
| Harassment or other conduct concern | Follow the [code of conduct](https://github.com/edithatogo/.github/blob/main/CODE_OF_CONDUCT.md) and its private reporting routes. |
| Shared defaults or standards defect | Open an issue in [`.github`](https://github.com/edithatogo/.github/issues) for these files, or [repository-standards](https://github.com/edithatogo/repository-standards/issues) for central policy and audit tooling. |

If a particular form is unavailable, a blank issue can be used for non-sensitive
questions and reports. Use the repository responsible for the affected feature
and link related issues instead of posting the same request repeatedly.

## What to include

Explain your goal, the version or commit, relevant environment details, the
commands or steps attempted, the expected result and what happened. Include a
small synthetic example where possible. Mention documentation already checked
and any workaround. Redact credentials, private source records and personal
information from text, screenshots, logs and attachments.

## Availability

These repositories are maintained by one developer. Support is provided as
capacity permits; no response time, implementation date or service-level
agreement is promised. A published template or research result does not imply
operational support for every deployment. Check local project guidance before
relying on a particular maintenance or compatibility commitment.

For contribution setup and PR expectations, see
[Contributing](https://github.com/edithatogo/.github/blob/main/CONTRIBUTING.md).
