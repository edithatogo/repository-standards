# Specification — Reproducible release and supply-chain evidence

## Requirement and contract
Make SBOMs, provenance and release authenticity verifiable by downstream consumers, not simply generated by a workflow. Separate reproducible build from publish; adapt to Python wheels, Rust crates, Node, containers, data and documentation output.

## Acceptance criteria
Canary verifier rejects mismatched provenance/artifacts; publication stays separate from validation; evidence bound to exact source and output digest; no unsupported SLSA-level claims.

## Boundaries and dependencies
- frontier_03_managed_remediation_20261113
- frontier_04_verification_harness_20261113

## Policy ownership
Central standards controls and evidence contracts only; consumer repositories retain their own product behavior, scientific correctness, and stronger controls. Write authority is separately gated. Never count scheduled/queued/unobserved checks as passed.
